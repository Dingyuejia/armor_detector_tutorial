# 怎么读 `solution` 分支

`solution` 是同一道题的一份完整实现（各场景成绩见 `docs/stages.md` 开头的
参照点表）。它**不是标准答案**：
同一个场景它也可能用别的方法做到同样好，而且它自己也有已知弱点（本文末）。

读它的正确方式是**带着自己的坑去读**，不是从头顺着看。所以下面按四轮走，
每轮只读一段，读完就去跑对应的场景——读完不能验收，等于没读。

单位是命中/秒（8 秒单次，`far` 的 9.00 已经贴着武器射速 10 发/秒的上限）。

---

## 第 0 步：先自己跑一遍，把猜测写下来

```bash
cmake -S . -B build && cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure     # core 绿、ideal_samples 红 = 正常
TAG=mine bench/run_all.sh                      # 每个场景都会是 0，但走一遍流程
```

然后**在动手写之前**，对着 `docs/stages.md` 给每个场景写一句"我猜它卡在哪一层"。
有了这个猜测，下面每读一段你都在验证/推翻自己，而不是被动接收。

---

## 数据是怎么流过去的

```text
frame ──▶ Observation ──▶ detect ──▶ solveArmor ──▶ tracker ──▶ 提前量+弹道 ──▶ Command
          (core/types.h)  (vision/)   (solver)       (tracker)    (pipeline)     │
                                                                                ▼
                                                        仿真伺服 a = ω²e + 2ω(goal_v − v)
```

第一轮读代码时，先把这条线上**每个箭头的输入输出类型**找出来。找不到就说明那段
还没读懂——而不是"这段不重要"。

---

## 第一轮：S1 距离与弹道（目标：`far` 从 0 到有）

读这两个函数，别的都先不要看：

1. `pipeline/solver.cpp` 的 `solveWithSpacing()`
   - 物体坐标那 4 个点是怎么摆的？为什么用灯条的**端点**而不是 `minAreaRect` 的四个角？
   - 相机在云台系里偏了 `camera_offset`，漏掉它 5 m 处会偏多少度？（0.46°，而纵向容差只有 0.68°）
   - 为什么用 `SOLVEPNP_IPPE`（平面目标）而不是通用 DLT？
2. `pipeline/solver.cpp` 的 `solveAim()`
   - 它比"指向目标的直线角"多抬了一个 `elevation`。为什么？
   - 为什么循环里要迭代？抬升角和飞行时间谁依赖谁？
   - 为什么水平距离要减掉 `barrel_length * cos(elevation)`？炮口不在旋转中心。

**验收**：`bench/run.sh far 8` 从 0 变成有命中；`static` 不能掉。
顺手做个小实验：把 `barrel_length` 当成 0 再跑 `far`，看掉多少——
这叫"知道每个修正项值多少分"。

---

## 第二轮：S2 关联与状态估计（目标：`spin` 不抖）

读 `pipeline/tracker.cpp`，重点只有两处：

1. `splitError()` + `update()` 里的关联
   - 门限为什么不是球形的？——PnP 的**深度**噪声是 0.1~0.3 m，垂直于视线的方向只有几厘米。
     用一个球形门限的后果是"深度一抖就判换板"，历史被清空，速度永远估不出来。
   - 门限失败时它做了什么？为什么不"等旧板转回来"？
     （自转 4 rad/s 时同一块板要 1.5 s 才转回来，那等于瞎了。）
2. `fit()`
   - 为什么用最小二乘直线拟合，而不是一阶滤波（alpha-beta）？
     提示：提前量对**速度**误差极其敏感，一阶滤波的速度分量带滞后。

再看 `pipeline/pipeline.cpp` 里候选的**排序**：为什么按 `cos_incidence` 降序，
而不是按 `matchArmors` 给的分数？想一想"首次锁定该锁哪一块板"。

**验收**：`bench/run.sh spin 8`；`bench/run.sh static 8` 不能掉。
自己录一段逐帧数据看云台的收敛时间和超调有没有变差。

---

## 第三轮：S3 提前量（目标：`translate`）

读 `pipeline/pipeline.cpp::estimate()` 的 3、4 两段，和 `command()` 的前馈：

- 提前量是解一个**不动点**：飞行时间依赖目标位置，目标位置依赖飞行时间。迭代几次？
- `flight + launch_delay + latency` 里三项各是什么？第三项（`latency_`）为什么必需？
  提示：观测是"过去"的，指令是"现在"发的，弹丸是"将来"到的。
  漏掉它的时候 `translate` 的落点偏差是 5.4 cm，补上是 4.0 cm。
- `yaw_rate` / `pitch_rate` 填进了 `Command::yaw_vel` / `pitch_vel`。去看仿真的伺服：
  `a = ω²e + 2ω(goal_v − v)`。**不填 `goal_v` 会怎样？** 稳态误差 `2·θ̇/ω`，
  在 4 rad/s 的自转靶上约 0.8°——比开火窗口还大。
- `command()` 的开火门控有四条，逐条问"去掉它会怎样"。

**验收**：`bench/run.sh translate 8`。**并且重复三次**——动态场景单次结果不可信。

---

## 第四轮：S4 生命周期（目标：不安事故）

这一轮最短，但最容易被跳过。读 `app/main.cpp` 的主循环和 `pipeline.cpp::command()`：

- 指令按 50 Hz 下发，帧率只有 ~55，中间帧复用旧指令。**凭什么认为那条旧指令还有效？**
- `kObservationTimeout` 为什么必须小于 250 ms？（仿真的指令看门狗是 250 ms）
- `session_id` 变了的时候发生了什么？不清历史会怎样？

**验收**（照 `docs/stages.md` S4 那节做）：把场景里的 `center` 改到 20 m，
确认它会停火而不是继续按上一条指令打。

---

## 三个"读的时候最容易忽略"的判断

这三条不是知识点，是**设计取舍**。它们各自的另一面都试过、都失败过：

| 判断 | 另一面长什么样 |
|---|---|
| 关联门限拆成"径向松 / 切向紧" | 球形门限 0.25 m → 一半的帧在重置跟踪，速度估不出来 |
| 开火残差门限**按距离归一**（`0.03 × distance`） | 绝对值 0.06 m → `far` 只打出 2 发（跟踪误差其实只有 0.16°） |
| 位置**不做**低通就直接拟合 | 加 50 ms EMA → `spin` 从 3.6 掉到 0.0（自转靶的切向在快速旋转，线性模型外推被低通坑死） |

---

## 怎么验证自己是"读懂了"而不是"看过了"

1. **改一个参数，预测哪个场景会掉，再跑。** 比如把 `kMinCosIncidence`
   从 0.25 提到 0.6：预测 `spin` 掉（板转到侧面就被丢）、`translate` 不变或更好。
   预测对了才算读懂。
2. **回答三个问题**（都能从代码里查到，但要自己想）：
   - 为什么开火门限是 0.6°，不是 1.5°？（算一下 5.25 m 处装甲板占多少度）
   - 为什么跟踪放在世界系，而不是图像系？
   - `solveAim` 的判别式 `disc < 0` 代表什么物理意义？
3. **把某个模块换成你自己的实现，其余不动**，看成绩变好还是变差。
   这是唯一能证明"你理解的是原理而不是这几行代码"的方法。

## `solution` 也没做好的地方（留给你）

诚实清单，别把它当上限：

- **`translate` 的落点偏差 5.0 cm**，而 5.58 m 处的容差只有 6.4~6.9 cm。
  余量很薄，命中率 0.78 左右。速度估计用的是线性模型，目标掉头时会有瞬态。
- **`combined` 的 3.88 是"关联策略"赚来的**，不是整车运动模型。
  目标急停/急转时线性速度模型会退化，那时需要估"整车旋转 + 平移"。
- **`hero` 大装甲没有专门验证**。代码里两种间距都试，但没有场景逼它。
- **`toofar` 还是 0**：7 m 处灯条只有 2 px 宽，卡在检测的物理极限，不是解算。
- **没有线程、没有延迟补偿建模、没有开火时机优化**。

## 一句话

读完 `solution` 你应该能回答这个问题：**"如果我把 `far` 的命中从 9 改到 9.5，需
要动哪里、会不会伤到 `static`？"** 答不出来，就说明还有一段没读进去。
